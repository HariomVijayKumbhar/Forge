# GitHub Integration Features for Forge

## Overview

Forge now includes comprehensive GitHub integration capabilities that enable seamless collaboration between the autonomous agent and GitHub repositories. These features enhance productivity by automating issue management, commit creation, release notes generation, and more.

---

## 🔗 Feature 1: GitHub Issues Auto-Assignment

### Purpose
Automatically link Forge runs to GitHub issues, post progress updates, and close issues upon successful completion.

### Key Endpoints

#### Link Run to Issue
```
POST /api/github/issue/link
Content-Type: application/json
Authorization: Bearer <TOKEN>

{
  "repo_url": "https://github.com/owner/repo",
  "issue_number": 42,
  "run_id": "run_abc123",
  "status": "in_progress"
}
```

**Response:**
```json
{
  "success": true,
  "run_id": "run_abc123",
  "issue_number": 42,
  "comment_url": "https://github.com/owner/repo/issues/42#issuecomment-123456"
}
```

#### Close Issue with Results
```
POST /api/github/issue/close
Content-Type: application/json
Authorization: Bearer <TOKEN>

{
  "repo_url": "https://github.com/owner/repo",
  "issue_number": 42,
  "run_id": "run_abc123",
  "summary": "Successfully implemented feature X",
  "success": true
}
```

**Response:**
```json
{
  "success": true,
  "closed": true,
  "comment_url": "https://github.com/owner/repo/issues/42#issuecomment-123457"
}
```

### Use Cases

1. **Issue Resolution Tracking**: Automatically post when Forge starts working on an issue
2. **Status Updates**: Keep issues updated with progress information
3. **Auto-Close**: Close issues when Forge successfully completes the task
4. **Error Reporting**: Add detailed error summaries if resolution fails

### Implementation Details

- Uses GitHub REST API v3 for comment creation and issue management
- Requires `GITHUB_TOKEN` with `issues:write` and `pull_requests:read` scopes
- Comments include run ID and status for tracking
- Automatically closes issues on successful completion

## 💾 Feature 2: GitHub Commit Integration

### Purpose
Create commits directly from Forge agent results and push changes to repositories.

### Endpoint

```
POST /api/github/commit/create
Content-Type: application/json
Authorization: Bearer <TOKEN>

{
  "repo_url": "https://github.com/owner/repo",
  "branch_name": "feature/auto-fixes",
  "file_changes": {
    "src/main.py": "def hello():\n    print('Hello')",
    "README.md": "# Updated README"
  },
  "commit_message": "Automated fixes: resolved issues #42, #43",
  "author_name": "Forge Agent"
}
```

**Response:**
```json
{
  "success": true,
  "commit_sha": "abc123def456",
  "branch": "feature/auto-fixes",
  "files_changed": 2
}
```

### Use Cases

1. **Code Fixes**: Automatically commit bug fixes
2. **Documentation Updates**: Update docs via agent
3. **Code Generation**: Commit generated code
4. **Bulk Changes**: Apply multiple file changes in one commit

### Implementation Details

- Uses GitHub Git Data API for reliable commit creation
- Supports multiple file changes in single commit
- Preserves commit history and parent relationships
- Includes author information and timestamps
- Works with any branch strategy

## 📝 Feature 4: GitHub Release Notes Generator

Automatically generate professional release notes from completed agent runs.

### Endpoint

```
POST /api/github/release/generate-notes
Content-Type: application/json
Authorization: Bearer <TOKEN>

{
  "repo_url": "https://github.com/owner/repo",
  "run_ids": ["run_123", "run_456"],
  "version": "2.5.0",
  "base_branch": "main"
}
```

**Response:**
```json
{
  "success": true,
  "release_url": "https://github.com/owner/repo/releases/tag/v2.5.0",
  "release_id": 987654,
  "version": "2.5.0"
```

### Generated Release Notes Format

```markdown
# Release 2.5.0

## Changes
- Run: `run_123`
- Run: `run_456`
```

### Use Cases

1. **Automated Release Publishing**: Create releases from runs
2. **Changelog Generation**: Track changes by runs
3. **Version Management**: Semantic versioning automation
4. **Release Announcements**: Professional release documentation

### Implementation Details

- Creates git tags and releases automatically
- Generates clean release notes
- Supports semantic versioning
- Integrates with GitHub Releases UI

## 📊 Feature 5: Repository Metadata & Insights

### Purpose
Fetch comprehensive repository statistics and insights for analytics and planning.

### Endpoints

#### Get Full Repository Metadata
```
GET /api/github/repo/metadata?repo_url=https://github.com/owner/repo
Authorization: Bearer <TOKEN>
```

**Response:**
```json
{
  "success": true,
  "name": "repo",
  "full_name": "owner/repo",
  "description": "Repository description",
  "stars": 150,
  "forks": 25,
  "watchers": 50,
  "open_issues": 12,
  "language": "Python",
  "languages": {
    "Python": 65000,
    "JavaScript": 35000
  },
  "contributors": 18,
  "created_at": "2023-01-01T00:00:00Z",
  "updated_at": "2024-01-15T10:30:00Z",
  "is_private": false,
  "is_fork": false,
  "url": "https://github.com/owner/repo"
}
```

#### Get Repository Languages
```
GET /api/github/repo/languages?repo_url=https://github.com/owner/repo
Authorization: Bearer <TOKEN>
```

**Response:**
```json
{
  "repo": "https://github.com/owner/repo",
  "primary_language": "Python",
  "languages": {
    "Python": 65000,
    "JavaScript": 35000,
    "TypeScript": 8000
  }
}
```

#### Get Repository Contributors
```
GET /api/github/repo/contributors?repo_url=https://github.com/owner/repo
Authorization: Bearer <TOKEN>
```

**Response:**
```json
{
  "repo": "https://github.com/owner/repo",
  "total_contributors": 18,
  "stars": 150,
  "forks": 25
}
```

### Use Cases

1. **Repository Analysis**: Understand repository structure
2. **Team Insights**: Identify contributors and activity
3. **Technology Stack**: Detect primary languages
4. **Project Health**: Monitor stars and engagement
5. **Planning**: Data for feature prioritization

### Implementation Details

- Aggregates data from multiple GitHub API endpoints
- Language statistics from GitHub's language detection
- Contributor counting with pagination support
- Cached results for performance
- Works with public and private repos

## 💬 Feature 6: GitHub Discussions Integration

### Purpose
Post agent run results and summaries to GitHub Discussions for community engagement.

### Endpoint

```
POST /api/github/discussion/post
Content-Type: application/json
Authorization: Bearer <TOKEN>

{
  "repo_url": "https://github.com/owner/repo",
  "category_name": "Announcements",
  "title": "Automated Feature: X Implemented",
  "body": "Forge agent has successfully implemented feature X.\n\n**Summary:**\n- Task completed\n- All tests passed\n- Ready for review"
}
```

**Response:**
```json
{
  "success": true,
  "discussion_url": "https://github.com/owner/repo/discussions/42",
  "discussion_id": "D_discussion123456"
}
```

### Supported Categories

- **Q&A**: Questions and answers
- **Show and Tell**: Showcasing work

### Use Cases

1. **Release Announcements**: Announce new features
2. **Community Updates**: Share progress with community
3. **Discussion Threads**: Organize feedback by topic
4. **Community Engagement**: Foster discussion
5. **Knowledge Sharing**: Document learnings

### Implementation Details

- Uses GitHub GraphQL API

- Automatic category detection
- Thread organization by category
- Community engagement features

## 🔐 Security & Configuration

### Required Environment Variables

```bash
# GitHub Authentication
GITHUB_TOKEN=ghp_xxxxxxxxxxxxx

```

### GitHub Token Scopes

The `GITHUB_TOKEN` should have the following scopes:

- `repo` - Full repo access (public and private)
- `workflow` - Read/write workflows
- `gist` - Gist access (optional)
- `user` - User information
- `discussion` - Discussion read/write

---

## 📈 Performance & Caching

### API Rate Limiting

- GitHub API has rate limits (60 req/hour unauthenticated, 5,000 authenticated)
- Implement caching for repository metadata
- Batch requests when possible
- Monitor X-RateLimit-Remaining headers

### Best Practices

1. **Cache Repository Metadata**: Refresh every 6 hours
2. **Batch Operations**: Combine multiple file changes in single commits
3. **API Processing**: Handle requests asynchronously
4. **Error Handling**: Gracefully handle API timeouts

## 🚀 Implementation Examples

### Example 1: Automated Issue Resolution Workflow

```python
# 1. Receive an issue from the Forge UI or API
# 2. Link run to issue
await github_client.link_run_to_issue(repo_url, issue_number, run_id)

# 3. Forge agent works on issue
# ... agent processing ...

# 4. Close issue with results
await github_client.close_issue_with_run_result(
    repo_url, issue_number, run_id, summary, success=True
)
```

### Example 2: Commit Generation from Agent Changes

```python
# Generate code changes
file_changes = {
    "src/utils.py": new_utils_content,
    "tests/test_utils.py": new_test_content,
}

# Create commit
result = await github_client.create_commit(
    repo_url="https://github.com/owner/repo",
    branch_name="feature/automation",
    file_changes=file_changes,
    commit_message="Automated refactoring: improved performance"
)
```

### Example 3: Release Workflow

```python
# After runs complete
results = [run_1, run_2, run_3]

# Generate release notes
notes_result = await github_client.generate_release_notes(
    repo_url, run_ids=[r.id for r in results], version="1.5.0"
)

# Create release with assets
release_result = await github_client.create_release_with_assets(
    repo_url, version="1.5.0", release_notes=notes_result
)

# Post to discussions
await github_client.post_to_discussion(
    repo_url, "Announcements", 
    f"Release {version} is now available",
    notes_result
)
```
